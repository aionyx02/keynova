## COMPLETED: PROFILE.2 — per-workspace pinned commands (ADR-0055)

Branch `feature/profile-2-pinned-commands` off `main`. A curated pin layer atop
the computed profile so a relied-on command is always one keystroke away even if
it drifts off the frequency ranking.

### Decision (ADR-0055, proposed)

Pins keyed by **slot** (not `project_root`): a pin is an explicit user act scoped
by the slot they curate, stored where the rest of per-slot state already lives,
stable before any project-tagged history exists. The computed profile underneath
stays project-keyed (ADR-0054).

### Backend

- `WorkspaceState.pinned_commands: Vec<String>` (`#[serde(default)]`, additive),
  `workspaces.json` version 2→3. `MAX_PINS = 8`, per slot.
- `WorkspaceManager::toggle_pin(command) -> bool` — add (most-recent first,
  capped) / remove; persists. Blank = no-op.
- `WorkspaceHandler` gains `workspace.pin { command }` → `{ pinned, commands }`;
  `workspace.get_current` already exposes `pinned_commands`. No allowlist to
  update (FEAT.GATE gates whole namespaces; `workspace` is open).
- Tests: `toggle_pin_adds_then_removes_per_slot`, `toggle_pin_caps_at_max`.

### Frontend

- `workspacePins.ts` — pure helpers: `commandKeyOf` (canonical `/name args` from
  a `cmd.run` replay), `pinToSuggestion` (mirror of backend `replay_for_row`,
  📌 marker + confidence 1.0), `mergeProfileWithPins` (prepend pins, drop the
  computed twin). `useWorkspacePins` hook loads via `workspace.get_current`
  (inlined async in the effect to satisfy `set-state-in-effect`), toggles via
  `workspace.pin`.
- Profile surface merges pins atop `workspace_profile.data` (capability itself
  untouched — no ranker change). Pin/unpin = **Ctrl+P** on the selected profile
  row, gated by a new `capabilityPinMode`/`onCapabilityTogglePin` pair in
  `useKeyboardNav` (idle `next` is not pinnable). Footer shows the `pinHint`.
- Discoverability follow-up (developer feedback: the Ctrl+P-only hint was too
  obscure for first-timers): `CapabilityListCard` gains an optional `pinControl`
  (only the profile surface passes it) → a clickable 📌 toggle on each pinnable
  row (filled when pinned, faint otherwise; `<span role=button>` sibling of the
  row button to avoid nested interactives) + a first-run onboarding banner shown
  until `anyPinned`. Title 📌 marker dropped (the button column now shows state).
  `togglePinAt(index)` backs both the button and Ctrl+P. i18n `pinOnboarding` /
  `pinAdd` / `pinRemove`.

- Lint fix: `togglePinSelected` depends on a stable boolean `profilePinActive`,

- Tests: `workspacePins.test.ts` (round-trip/merge/dedupe), `useKeyboardNav`
