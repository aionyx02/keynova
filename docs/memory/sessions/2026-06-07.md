## COMPLETED: CONT.2 - window resize coalescing

`useWindowResize` fired a native `setSize` per DOM mutation → the OS window
chased content height and jittered during streaming / result population. Now it
tracks last applied width/height and: grows immediately on first sizing /
deliberate width change / ≥4px growth, debounces a ≥24px shrink by 90ms (so a
one-frame dip between batches doesn't flicker), and skips sub-threshold changes.
Terminal modes keep deterministic sizes. **Needs `tauri dev` confirmation of
feel** (logic-only change; cannot be unit-verified). lint + 206 FE tests + build
pass.

## CONT.2b - Ctrl+K close-then-reopen race (debounce kept; under diagnosis)

Developer reported Ctrl+K sometimes closes then instantly reopens. First attempt
added a 180ms toggle **debounce** (`AppState.last_launcher_toggle`) plus a
focus-aware toggle. It did **not** fix it.

Analysis: the in-app handler does exactly one action per press (and the debounce
collapses a double-fire), so a hide-then-show on one press must come from a
**separate show path**. Candidates that call `show_launcher` independently of the
global shortcut: `single_instance` (second-launch), `control_server` `Start`
(sent by the `keynova` CLI bin), tray, and the blur-guard re-show. A likely cause
is an **OS-level / CLI Ctrl+K** firing alongside the app's built-in shortcut
(in-app hide + external show).

Changes this pass:

- Reverted the focus-aware branch — `is_focused()` blips on Windows/WebView2, so
  the toggle is back to the reliable `is_visible()` form; the **debounce stays**.
- Added temporary `[keynova] …` diagnostics to every show/hide path (ctrl+k
  toggle + decision, `show_launcher_window`, `hide_launcher_window`,
  `single_instance`, `control_server` Start, blur-guard re-show) so one
  `tauri dev` press pinpoints the reopener. Remove once root cause is fixed.

Next: developer rebuilds, presses Ctrl+K once, pastes the `[keynova]` lines; and
confirms whether Ctrl+K is bound at the OS level to launch Keynova or only via
the app's built-in shortcut. 534 Rust tests + clippy clean; build OK.

**Defensive guard added** (source-independent): `AppState.launcher_toggled_within`
+ the external show paths (`single_instance` second-launch, `control_server`
`Start`) now drop a show that lands within 400ms of an in-app Ctrl+K toggle —
i.e. the "show" that echoes the same physical key press and reopens a
just-closed window. The in-app global shortcut fires first (in-process) and
stamps `last_launcher_toggle`; the slower external launch is then suppressed.
Legitimate CLI `keynova start` from a terminal (no recent toggle) still shows.

**FIXED, confirmed by developer.** The close-then-reopen race is resolved.
Final shape (kept): `is_visible()` toggle + 180ms debounce + the toggle-echo
guard on the external show paths. The temporary `[keynova]` show/hide trace logs
were removed after confirmation; only the pre-existing error logs remain. 534
Rust tests + clippy clean.

## COMPLETED: PRODUCT.4.A - frequency + workspace-affinity ranking

Branch `feature/product-4-ranking` (from `main`). Extends the CONT.1 transition
ranker in `suggest_next` with two signals derived from the existing history
window — **no schema change** (success-rate, which needs a column, is split to
4.B):

- **Frequency**: occurrence count per `(route, action_label)` in the window,
  log-normalized (`ln_1p`) so one very frequent action can't dominate; weighted
  `FREQUENCY_WEIGHT`. Surfaced as "used N×" in the row subtitle.
- **Workspace affinity**: candidates whose `workspace_id` matches the anchor
  (most-recent) row's workspace get `WORKSPACE_WEIGHT` — looser than the exact
  `same_context` hash.
- Rescaled `score_row` recency to ~half magnitude and dropped its early clamp so
  the transition/frequency/workspace signals are not saturated by recency; the
  final blend is clamped once. CONT.1 transition tests still pass.

+2 pure unit tests (frequency lifts a habitual action above a recent rare one;
same-workspace outranks other-workspace). 543 Rust tests + clippy clean; lint +
206 FE tests + build green. The idle/`next` card already renders the subtitle, so
