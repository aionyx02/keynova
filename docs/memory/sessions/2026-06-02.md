# Session 2026-06-02

## Completed: REF.9 Security Hardening

Network and settings:

- Added `core/network_policy.rs` and wired outbound URL checks through AI, model, translation, agent web/search, Nvim, startup preflight, and portable Nvim paths.
- Added `security.network_allowlist` to default config and schema.
- Added schema/type/options validation for user-facing `setting.set` and `/setting key value`.
- Protected `security.*` settings from user-facing mutation while keeping trusted backend config writes available.

Terminal and launcher:

- `TerminalLaunchSpec` is now registered by the backend when a command result returns `CommandUiType::Terminal`.
- `terminal.open` with a launch spec consumes the registered spec once and rejects unregistered or mutated specs.
- `terminal.open` without a backend-issued launch spec is rejected; terminal prewarm/default shell startup was removed.
- The frontend no longer builds renderer-generated terminal launch specs for generated shell commands.
- Public `launcher.launch` now accepts only cached application paths; backend-issued action refs use internal trusted launch for search results.

Mouse, control plane, automation:

- `mouse.*` routes now require `mouse_active`; direct IPC while inactive fails before sending HID input.
- Control-plane requests now include a per-user token stored under the Keynova config directory.
- Automation TOML and pipeline execution now validate routes against an allowlist and block high-risk routes such as `terminal.*`, `mouse.*`, `launcher.launch`, and `setting.set`.

Secrets and local files:

- Added `core/secret_store.rs` using the OS keychain via `keyring`.
- Sensitive config writes store the secret in the OS keychain and persist `keyring:keynova:<key>` in `config.toml`.
- Existing plaintext sensitive settings migrate to keychain on normal startup.
- `learning_material.preview` now requires enabled local-context review plus approved roots and canonical root-prefix checks.
- `learning_material.export_markdown` is limited to `.md` / `.markdown` files under the NoteManager notes root.

Destructive commands and Windows process launch:

- `/killport <port> kill` was changed to a preview-only builtin; direct termination now requires a future backend approval flow.
- Updated low-level `process_lookup::kill_pid` comments to clarify that callers must enforce backend approval.
- Windows portable-Nvim extraction now passes archive/destination via environment variables instead of interpolated PowerShell strings.

Stability and tooling:

- `startup_preflight` caches the process boot id so same-boot snapshot reuse is not broken by `sysinfo::System::boot_time()` one-second drift.
- Upgraded `vitest` to `^4.1.8` and refreshed `package-lock.json`; `npm audit` reports zero vulnerabilities.

## Completed: Security Hardening Wave A (review items #3 / #5 / #6)

Complementary follow-up to the `68ff44e` pass — the three lower-risk review
items it did not cover. Branch `feature/sec-hardening-a` off `main`.

- #3 Windows launch injection: `platform/windows/apps.rs::launch_app` now uses
  `tauri_plugin_opener::open_path` (ShellExecute semantics) instead of
  `cmd /C start "" <path>`, so paths with shell metacharacters (`&`, etc.)
  can't be reinterpreted by cmd.exe. Non-windows launch was already shell-free.
- #5 Portable Neovim integrity: pinned per-platform SHA-256 of the v0.10.4
  archives (from neovim's `<asset>.sha256sum`) in `portable_nvim_manager.rs`;
  the download is verified before extraction, mismatch deletes + aborts.
  Complements `68ff44e`'s network-allowlist on the download URL.
- #6 CSP: narrowed `connect-src` from `http://localhost:* ws://localhost:*`
  to the fixed vite dev port `:1420`. The webview only needs localhost for dev
  HMR — Ollama and all backend HTTP go through Tauri IPC (reqwest in Rust),
  never the renderer — so this removes arbitrary local-port reach with no
  runtime loss. `msSmartScreenProtection` left disabled on purpose (a
  documented v0.3.0 perf/memory measure; marginal benefit for a local-content
  webview).

Still open from the review (candidate wave B): #1 asset-protocol scope is still
`["**"]` + `file.preview` returns raw image paths to the renderer (needs scope
narrowing + opaque preview token); #2's string-setting validation gap remains
even though the terminal-spec execution path is now gated by `68ff44e`.

Verified (wave A): `cargo test --lib` 452 passed / 0 failed / 2 ignored,
`clippy --lib -D warnings` clean, `cargo check --all-targets` clean, rustfmt clean.

## Completed: Security Hardening Wave B (review item #1 + #2 residual)

Branch `feature/sec-hardening-b` off `main`. Closes the highest-severity review
item (#1) plus the #2 string-validation residual. Design recorded in
`docs/adr/0042-asset-protocol-removal-inline-preview.md` (proposed; implemented
under explicit developer direction in-conversation, formal acceptance pending).

- #1 asset protocol / preview path exposure: the asset protocol's only consumer
  was `PreviewPane` image rendering via `convertFileSrc(preview.path)`. Switched
  image previews to a backend-produced bounded base64 `data:` URL —
  `file.preview` (`handlers/file.rs`) returns `data_url` (≤ 8 MiB; larger →
  `oversized: true`, metadata only) and no longer returns a `path` for images.
  `PreviewPane.tsx` renders `data_url` and drops `convertFileSrc`;
  `useFilePreview` now keys its cache by the requested result path.
  `tauri.conf.json`: `assetProtocol.enable = false` (scope `["**"]` removed) and
  CSP `img-src` dropped `asset:` / `asset.localhost` (keeps `'self' data:`).
  The renderer can no longer load arbitrary local paths via the asset protocol.
- #2 residual: `validate_user_setting_value` now rejects shell metacharacters /
  control chars (`; & | < > $` backtick, control) for the command-path keys
  `terminal.default_shell` and `notes.lazyvim_command` — defense-in-depth on top
  of `68ff44e`'s backend-issued terminal-spec gating. Spaces/quotes (paths) stay
  allowed.

Verified (wave B): `cargo test --lib` 452 passed / 0 failed / 2 ignored,
`clippy --lib -D warnings` clean, rustfmt clean; `npm run build` clean (tsc +
vite), `npm test` 163 passed / 1 skipped.

Residual / follow-up: `file.preview` still previews any existing path the
renderer requests (bounded, backend-mediated); constraining preview to approved
roots is an optional later hardening, noted in ADR-0042 §3.
