# Session 2026-06-13

## COMPLETED: SPAWN.NOWINDOW - suppress black console flash on Windows subprocess spawns

### Problem

On Windows with a cold icon cache (e.g. right after install), startup pre-warm
(`warm_icon_cache` → `run_icon_script`, `platform/windows/icon.rs`) spawns one
`powershell.exe` per icon: 1 folder + 31 file extensions + every scanned app
(commonly 50–80+ processes), each via a blocking `.output()`.

None of the spawns set the Windows `CREATE_NO_WINDOW` creation flag, so every one
**flashes a black console window**. Each console grabs foreground focus; the
Keynova overlay hides/closes on blur, so opening Keynova during pre-warm makes the
window vanish — the user-reported "crash". The same missing-flag bug was latent at
~10 other runtime spawn sites (`wmic`, `nvidia-smi`, brightness `powershell`,
`netsh`, `wsl.exe`, `taskkill`/`netstat`/`tasklist`, bounded dev runner, Windows
sandbox exec).

### Fix

`std::os::windows::process::CommandExt::creation_flags(0x0800_0000)` is the canonical
fix. Added one shared cross-platform extension trait so every spawn opts in with a
single chained call; no-op on non-Windows.

- New `src-tauri/src/core/proc.rs`: `SilentCommandExt::no_window()`
  (`#[cfg(windows)]` sets `CREATE_NO_WINDOW`; else returns `self`). Re-exported from
  `core/mod.rs`.
- Applied `.no_window()` at every Windows `std::process::Command` spawn site:
  `platform/windows/icon.rs` (the primary fix), `managers/model_manager.rs` (wmic
  ×2, nvidia-smi, powershell), `managers/system_manager.rs` (brightness ×2, netsh
  wifi), `platform/windows/fileindex.rs` (wsl.exe), `core/process_lookup.rs`
  (taskkill/netstat/tasklist), `core/dev_runner.rs`, `managers/sandbox_manager.rs`
  (Windows `imp::run`).
- Skipped: non-Windows-only spawn sites (`sysctl`, `kill`, `lsof`, Unix sandbox
  poll runner, Unix CLI indexer, non-Windows app launch) and the GUI-subsystem
  launcher in `bin/keynova.rs` (no console; separate crate).

### Decisions

- Chose "hide windows only" over a native `SHGetFileInfo` rewrite (user choice).
  The flag fully resolves the black-popup + focus-steal crash. Removing the 50–80
  per-startup process spawns via native HICON→PNG is a deferred perf follow-up
  (`backlog`: SEARCH.ICON.NATIVE).
- Did **not** move pre-warm into the installer: installer runs in a different
  user/elevated context so `dirs::cache_dir()` wouldn't match the runtime cache,
  the app list is incomplete at install time, and it wouldn't fix the other
  runtime console-flash sites. Once spawns are windowless, warm runs invisibly in
  the background and the crash is gone.
