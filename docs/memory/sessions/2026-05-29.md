## Detailed Notes

### Backend capability layer

- Added `src-tauri/src/core/ai_capability/capabilities/gen_command.rs`.
  - Accepts `{ intent, ctx }`.
  - Returns structured `{ command, confidence, rationale }`.
  - Uses a JSON-first prompt/parse flow with a non-JSON fallback so local-model variance does not hard-fail the capability.
  - Audits like the other risky capability paths.
  - Computes a conservative `RiskTag`: clearly read-only commands (`git status`, `cargo test`, etc.) return `requires_confirmation = false`; everything else falls back to confirm.
- Added `src-tauri/src/core/ai_capability/capabilities/suggest_next.rs`.
  - Accepts `{ ctx: { limit? } }` plus the existing optional `context_hash`.
  - Reads `workflow_memory::suggest`.
  - Heuristically ranks recent rows, dedupes identical `(route, title)` pairs, and emits structured suggestion rows.
  - Adds best-effort replay descriptors for replayable `cmd.run` rows.
- Expanded the compile-time registry and dispatcher to all 5 capabilities: `explain`, `summarize`, `fix_error`, `gen_command`, `suggest_next`.

### Workflow-memory follow-through

- `src-tauri/src/app/dispatch.rs` now records richer workflow-history labels:
  - `cmd.run` stores `/name args` instead of just `name`.
  - `capability.call` stores `id + excerpt` when a useful text field exists.
  - `action.run` derives labels from the resolved action kind (for example `Open main.rs` instead of a generic `Open`).
- This stayed schema-compatible: no migration was needed, only better new writes.

### Frontend surface prep

- `src/features/ai-capability/types.ts`
  - Added `gen_command` / `suggest_next` ids.
  - Added payload/output interfaces for both capabilities.
  - Added runtime parsers for structured outputs.
- Added `useGenCommand.ts` and `useSuggestNext.ts` as thin wrappers over `useCapability`.
- Added `src/features/ai-capability/types.test.ts` for the new structured parsers.

### Frontend palette wiring

- Extended `parseCapabilityPrefix` / `usePaletteMode` so `cmd <intent>` and zero-arg `next` now enter capability mode instead of falling back to search.
- Added `src/features/ai-capability/CapabilityCommandCard.tsx`.
  - Renders structured `{ command, confidence, rationale }`.
  - Supports `Run`, `Edit before`, and `Copy`.
  - `Run` opens an attached terminal launch spec instead of trying to execute inline.
- Added `src/features/ai-capability/CapabilityListCard.tsx`.
  - Renders ranked `suggest_next` rows.
  - Auto-loads when typing `next`.
  - Supports arrow-key selection and replay for rows that expose a replay descriptor.
- Added `src/features/ai-capability/hooks/useCapabilityRunState.ts` to track non-streaming submit/cancel timing for `cmd` and `next`.
- `src/components/CommandPalette.tsx` now lifts all three capability scenes:
  - streaming text (`explain` / `summarize`)
  - structured command generation (`cmd`)
  - workflow suggestions (`next`)
- `src/features/command-palette/hooks/useKeyboardNav.ts` now distinguishes between Enter-to-submit capability cards and Enter-to-replay `next` rows.
- Added `src/features/command-palette/utils/looksLikeAiCommandIntent.ts` plus tests so the palette can distinguish a plain search from an action-style natural-language intent.
- `src/components/CommandPalette.tsx` now auto-mounts:
  - `next` on an empty palette
  - `cmd` when a stabilized natural-language action query still has no results
- The smart `cmd` path is submit-on-Enter, not auto-fire, so it lowers friction without spamming the model on every typing pause.
