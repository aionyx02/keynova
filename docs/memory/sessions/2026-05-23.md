## Detailed Notes

### Backend module shape

- `core/ai_capability/mod.rs` — single public entry `call_capability(req, deps)`; compile-time `match` on `CapabilityId` (enum-based registry, no `dyn Capability`).
- `core/ai_capability/registry.rs` — `CapabilityId::{Explain,Summarize,FixError}` + static `CapabilityMeta` table; `meta(id).audit` and `accepts_context_hash` are fixed at registration per ADR-0030 §4, never returned per-call.
- `core/ai_capability/contract.rs` — `CapabilityRequest`, `CapabilityResponse`, `CapabilityOutput::{Text,Structured}`, `CapabilityError::{UnknownId,InvalidPayload,ProviderError,Cancelled,UnsupportedAction}`. `ChatProvider` trait abstracts the LLM call so unit tests can stub; production impl is `AiManagerChatProvider` wrapping `AiManager::chat_sync` / `chat_sync_stream`. `StreamChunkFn` alias keeps clippy `type_complexity` happy.
- `core/ai_capability/prompt.rs` — `CAPABILITY_PROMPT_BUDGET_CHARS = 1400`, `CAPABILITY_PROMPT_SOURCE_LIMIT = 6`, `CAPABILITY_SNIPPET_MAX_CHARS = 160`. Budget overrun drops the context block first, then truncates the task body via `core::grounding::truncate` (char-boundary safe). `maybe_audit` writes through `KnowledgeStoreHandle::try_log_agent_audit` only when `audit_required == true`.

### Capabilities

- `explain` — pulls workspace/commands/notes/history sources via `LocalContextSearcher`, best-effort (errors non-fatal). `audit = true`, `risk_tag = none()`.
- `summarize` — pure text transform, no local grounding. `audit = false`, `risk_tag = none()`.
- `fix_error` — accepts either `{raw_output}` (preferred, no exec) or `{program,args,cwd,timeout_secs}` which re-runs via `core::dev_runner::run_bounded_dev_cmd`. Program allowlist: `cargo`, `npm`, `pnpm`, `yarn`, `tsc`. Any `{apply:...}` variant returns `UnsupportedAction` (file-mutating fix path deferred to a future ADR). `audit = true`, `risk_tag = none()`.

### Handler + wiring

- `handlers/ai_capability.rs` — `capability.list` / `capability.call` / `capability.cancel`. Worker is `std::thread::spawn`; per-`request_id` `Arc<AtomicBool>` cancel flag in a `HashMap`. No global single-flight — distinct request ids may run in parallel; per-chip UI disable owns serialization (ADR-0029 §4 state-based). Streaming emits `capability.stream.chunk` events; terminal event is `capability.response`.
- `core/local_context.rs` — added `#[derive(Clone)]` so the handler can clone the searcher into each spawned thread cheaply (all fields are already `Arc`).
- `managers/ai_manager.rs` — added `chat_sync` + `chat_sync_stream` blocking shims (single-user-turn, no history mutation; reuse existing `do_chat` / `do_chat_stream`).
- `app/state.rs` — registered `AiCapabilityHandler` with `LocalContextSearcher` constructed from the same managers the agent handler uses, plus `KnowledgeStoreHandle` and the event bus.
- `core/mod.rs`, `handlers/mod.rs` — exposed the new modules.

### Frontend feature

- `src/features/ai-capability/types.ts` — TS twin (`CapabilityId`, `CapabilityMeta`, `CapabilityOutput`, request/response event payloads, per-capability payload types). Re-uses `RiskTag` and `parseRiskTagFailSafe` from `src/types/unified-result.ts` — no duplication.
- `src/features/ai-capability/hooks/useCapability.ts` — generic single-call hook. State-based `isLoading` for ADR-0029 §4 in-flight disable. Subscribes to `capability.response` (filtered by `request_id`) + optionally `capability.stream.chunk`. Outside Tauri (`window.__TAURI_INTERNALS__` absent) it short-circuits listener setup, matching the jsdom pattern in `useSearchBackend`.
- `src/ipc/routes.ts` — added `CAPABILITY_LIST` / `CAPABILITY_CALL` / `CAPABILITY_CANCEL`.

Ran against the only model currently installed locally (`qwen2.5:0.5b`, ~400 MB) to validate the end-to-end pipeline. `qwen2.5:7b` was not pulled this session; the canonical ADR-0029 §8 reading remains pending.

|---|---|---|
| `explain` | 4650 ms | text reply, `risk_tag.requires_confirmation = false` |
| `fix_error` (raw cargo E0308) | 4998 ms | text reply, `risk_tag.requires_confirmation = false` |

Interpretation:
- End-to-end pipeline (`capability.call` → `AiManagerChatProvider::chat` → `do_chat` → Ollama HTTP → response) works against a real daemon. No code changes needed after the smoke.

- Numbers are nowhere near the 800 ms P50 budget but **not informative for the ADR target** — a 0.5b model on CPU at ~20 tok/s easily takes 3–4 s to produce 60+ output tokens regardless of model load. The 7b reading must be retaken on hardware that actually serves it (GPU / Metal) before any conclusion.

## COMPLETED: REF.5 - Workflow memory (schema v4 + record/suggest, backend + hooks only)

Workflow memory lands as the second backend-only batch (no `CommandPalette.tsx` mount, REF.6 will wire the surface). 11 backend tests + 5 frontend hook tests green; clippy `-D warnings` + npm lint clean.

### Schema v4

- Bumped `CURRENT_SCHEMA_VERSION` 3 → 4 in `src-tauri/src/core/knowledge_store.rs`.
- Appended `workflow_history` DDL + two indexes to `init_schema()` (`idx_workflow_history_context (context_hash, executed_at DESC)`, `idx_workflow_history_executed (executed_at DESC)`).
- Migration uses the existing auto-backup path: on next open of an existing v3 DB, `open_connection()` creates `…-v3-to-v4-{uuid}.db` under the store's `backups/` dir, runs the idempotent DDL, and records the v4 row in `schema_migrations`. **No down-migration code exists** — rollback guidance per ADR-0029 §4 is "open the auto-backup, or `DROP TABLE workflow_history;` + `PRAGMA user_version = 3`." v3 tables are untouched (purely additive).

### Module split

- `src-tauri/src/core/knowledge_store.rs` — added `WorkflowHistoryEntry`, `WorkflowHistoryRow`, `DbRequest::{WriteWorkflowHistory, ReadRecentWorkflows}`, `KnowledgeStoreHandle::{try_log_workflow_history, recent_workflows, recent_workflows_blocking}`, `insert_workflow_history` + `read_recent_workflows` SQL. Mirrors the agent-audit pattern.
- `src-tauri/src/core/workflow_memory.rs` — `compute_context_hash(workspace_id, mode, panel)` (DefaultHasher; coarse on purpose), `digest_payload(payload)` (deterministic via canonical serde), `record`, `suggest`, `clamp_limit`. `DEFAULT_LIMIT = 5`, `MAX_LIMIT = 50`.
- `src-tauri/src/handlers/workflow_memory.rs` — `workflow.recent` + `workflow.suggest`. Suggest resolves `context_hash` server-side from `WorkspaceManager::current()` so frontend never has to know the hash formula.

### Record hook

- `cmd_dispatch_impl` Ok branch in `src-tauri/src/app/dispatch.rs` — central hook for routes `cmd.run` (label = `payload.name`) and `capability.call` (label = `payload.id`). Payload is cloned cheaply only when route is on the allowlist.
- `run_action_command` Ok branch — second hook for `action.run` where the resolved `action.label` is at hand (avoids double action_arena resolution).
- `record_workflow_event` helper swallows workspace-lock failures: workflow recording is best-effort and must never block the critical IPC path. Lock failure → entry recorded without `context_hash` + `workspace_id`.

### Frontend

- `src/features/workflow-memory/types.ts` — `WorkflowHistoryRow` + `WorkflowSuggestResponse`.
- `src/features/workflow-memory/hooks/useWorkflowMemory.ts` — `useRecentWorkflows()` + `useSuggestedWorkflows()` produced by a `makeWorkflowQueryHook(route)` factory (renamed from `useWorkflowQuery` to avoid ESLint rules-of-hooks false-positive on the factory). Outside Tauri the hooks short-circuit to empty rows (same jsdom pattern as `useSearchBackend` + REF.4 `useCapability`).
