### Later in the session — inline AI UI pivot

After the initial re-plan, the developer flagged that the docx §4.1–4.5
"per-row Explain chip + auto-detect" mockups are NOT what they want. The
target pattern is prefix-keyword: type `explain <question>` (or `cmd` /
`fix` / `summarize` / `next`) in the palette → Gemini-style streaming
answer card occupies the result area. No row chips, no auto-detect.

Decisions captured via AskUserQuestion:

1. **Result area ownership in capability mode**: only the answer card —
   capability mode does not show normal search results in parallel.
2. **Prefix coverage**: all 5 capabilities use prefix keywords for
   consistency (`explain`, `summarize`, `cmd`, `fix`, `next`).
3. **REF.6.A row chip + Ctrl+E**: removed entirely. UnifiedResult wire
   format from REF.6.A is retained (still useful for action data on rows
   via secondary menu); only the chip rendering and Ctrl+E binding go.

Spec file `docs/tasks/refactor-ai-capability-ui-spec.md` rewritten
end-to-end against the new pattern. Main plan file's REF.6.B/D/E/F
sub-batch descriptions revised in lockstep. `current.md` notes a third
intentional deviation from docx literal text. New memory
`feedback-inline-ai-prefix` records the durable rule so future agents
do not re-introduce per-row AI chips.
