## COMPLETED: BUGFIX.SECRET - keyring credential-store backend (secrets now persist)

Translation (and every other sensitive) API key read back empty even though the
settings UI showed it as `Set`, so `translate` reported "Translation API key not
configured". Root cause was a misconfigured dependency, not app logic.

### Root cause

`src-tauri/Cargo.toml` declared `keyring = "3"` with no credential-store feature.
keyring 3.x compiles fine without a backend but silently falls back to an
in-memory **mock** keystore. `secret_store::store_secret` returned `Ok` and the
config map kept the `keyring:keynova:<key>` reference (so the UI `Set` badge and
the redaction mask both showed "configured"), but the value never reached the OS
keychain. On the next read — or the next process — `keyring::Entry::get_password`
hit a fresh/empty mock store, so `resolve_secret_value` returned `""` and
`runtime_config().api_key` was empty.

### Fix

Wire each platform to its native backend via target-specific dependency tables so
non-target deps (Linux dbus/secret-service) aren't built elsewhere:

- base: `keyring = { version = "3", default-features = false }`
- `cfg(windows)`: `features = ["windows-native"]` (pulls `windows-sys` + `byteorder`)
- `cfg(macos)`: `features = ["apple-native"]`
- `cfg(linux)`: `features = ["sync-secret-service", "crypto-rust"]`

Verified `cargo tree -p keyring` now shows `byteorder` + `windows-sys` (the
windows-native backend) instead of the mock store. `cargo build`, `cargo clippy
-- -D warnings`, and the `secret` test suite all pass.

### Follow-up for the user (one-time)

Any secret stored before this fix only ever lived in the now-discarded mock store,
yet `config.toml` still holds its `keyring:keynova:<key>` reference. The UI will
keep showing `Set` while the real keychain is empty, so the key must be
re-entered once via `/setting → translation.api_key`; after that it persists to
Windows Credential Manager and round-trips correctly.

### Relationship to 9529ac8

Commit `9529ac8` (show stored secrets as `Set` instead of blank) was the display
half. This is the functional half — the value now actually persists. Governed by
ADR-0041 (secret-at-rest); no new ADR (keyring was already a dependency, only its
backend feature was enabled).
