## SEC.4（部分）：關掉 SEC.3 記錄的缺口

### 1. `.gitignore` agent 組態區塊

補上 `.mcp.json`、`.cursor/`、`.cursorrules`、`.amazonq/`、`.windsurf/`、
`.windsurfrules`、`.roo/`、`.aider*`、`.github/copilot-instructions.md`，與既有的
`.claude/`、`AGENTS.md` 合併成一個帶說明的區塊。順手修掉原本第 59 行那句反過來的註解
（「Personal notes are intentionally tracked.」寫在 `AGENTS.md` 這條 ignore 上面）。
無檔案受影響——這些路徑目前都不存在。

### 2. `.github/workflows/audit.yml`

兩個 job：`npm audit --audit-level=high`（+ `npm audit signatures` 為
`continue-on-error`）與 `cargo audit`。觸發為 main/dev push + PR + 每週一 07:05 UTC
（錯開 CodeQL 的 06:17）+ `workflow_dispatch`，刻意不掛在每次 push：advisory 狀態隨
資料庫變動而非隨 commit 變動。

兩個刻意的選擇：

- `npm ci --ignore-scripts`——這個 job 的工作就是稽核依賴樹，不該在稽核前先執行
  第三方的 lifecycle script。
- `cargo-audit` 用 `cargo install --locked` 而非第三方 action：這個 workflow 本身是
  供應鏈閘門，不該為了省事再引入一個新的供應鏈。靠 `swatinem/rust-cache` 的
  `cache-bin` 攤平首次編譯成本。

YAML 以 `js-yaml`（node_modules 既有）解析驗證通過；`cargo audit` 那半未在本機執行
（無 `cargo-audit`），首次 CI 跑完需確認。

### 3. 依賴修補（新閘門立刻抓到的東西）

`SEC.1` 記錄的 2026-06-10「npm audit = 0 vulnerabilities」已經過期：今天重測是
**9 個（2 low / 7 high）**。全部是 build/test 工具鏈的間接依賴，沒有一個進 runtime
bundle：`@babel/core`、`brace-expansion`、`esbuild`、`form-data`、`js-yaml`、
`nanoid`、`postcss`、`vite`、`ws`。

九個都有 semver 範圍內的修法，符合 `SEC.1` 既定政策（只做安全的 in-range 升級），
故執行 `npm audit fix`（**不加 `--force`**）：改動 30 個套件、只動
`package-lock.json`，`package.json` 的版本區間一字未改。修補後 `npm audit` 回到 0。

驗證：`npm run check`（eslint + tsc + vite build）通過；`vitest` 218 tests 全過。
第一次跑 vitest 時 `CapabilityAnswerCard.test.tsx` 的 "renders streaming text as
markdown" 失敗一次——升級後首跑的 import 成本約 50s，`findByText` 預設 1s timeout
被拖爆。重跑全套 218/218 綠，該檔案單獨連跑 3 次皆 14/14。判定為冷啟動 flake，
非升級造成的迴歸。Rust 端未受影響（只動 npm 依賴），故未跑 cargo。

### 4. ADR-0057（提議，未實作）

拆 `security.csp` / `security.devCsp`。稽核時的關鍵發現讓這份 ADR 比原本預期的更進一步：

- renderer 端 **完全沒有** `fetch(` / `XMLHttpRequest` / `new WebSocket`（排除測試後
  全域搜尋）。所有外連都由 Rust 後端發出（`handlers/model.rs`、`handlers/translation.rs`、
  `managers/ai_manager.rs`），走 `core/network_policy.rs` 的 host allowlist。
- 因此 production `connect-src` 不只該拿掉 dev origin，那四個遠端 host
  （anthropic / openai / 兩個 googleapis）也是純多餘——對照組是 Ollama
  （`localhost:11434`）從來不在 `connect-src` 而功能正常。
- `devCsp` 是 Tauri 2 原生欄位（在 `@tauri-apps/cli/config.schema.json` 的
  `SecurityConfig` 確認過），不需自建建置步驟。

依 governance §3，ADR 維持 `提議`，`tauri.conf.json` 未動。
