ADR 決策預覽模板

這是 proposed ADR 的視覺輔助頁。正式決策、狀態與實作授權仍以 Markdown ADR 為準。

預期成果

  • 接受此 ADR 後，使用者體感會長什麼樣子。
  • 實作完成後，模組、資料契約或權限邊界應該變成什麼樣子。
  • 哪些東西明確不應該改。

決策選項

  • 方案 A：維持現狀或最小改動。
  • 方案 B：建議採用路線。
  • 方案 C：被排除但需要記錄的替代方案。

風險與回滾

  • 最高風險的行為、資料契約或安全邊界。
  • 回滾開關、migration 反向策略或相容視窗。
  • merge 前需要人工確認的項目。

驗證關卡

  • npm run docs:refresh
  • 對應的 unit / integration checks。
  • 使用者可見行為的手動流程檢查。

預期檔案形狀

正式改 runtime code 前，先列出預期新增、修改、搬移、刪除的檔案與原因。
